## R3：人工评审 + 定向修复（选手完成）

按赛题规则「选手负责评审代码、排查修复 AI 幻觉 bug」，本轮由我直接改代码，共 8 处：

| 改动 | 原因 |
| --- | --- |
| 休眠改「可等待定时器（高精度）+ 末段自旋」 | 解决 15.6ms 粒度导致的帧率抖动 |
| `clear_canvas` 改为整幅清空 | 消除 `draw_pixel` 判界大于可见区造成的幽灵像素 |
| 退出不再 `clear_screen()` | 保留最后一帧，便于观察与截图 |
| 爆炸点 y 夹到 ≥1 | 避免整团粒子出生即销毁 |
| 64 等分单位圆方向表 | 粒子等角发射，爆裂从「随机散点」变成放射状，且不引入 `math.h/libm` |
| 纵向速度 ×0.55 | 终端字符高约为宽 2 倍，压缩后爆炸轮廓接近圆形 |
| 亮度阈值收窄 + 余烬最后 1/3 降一档 | 强化 `@ O o * , .` 层次 |
| 火箭加两格尾焰（`o`、`,`） | 上升阶段可读性更好 |

调参前后对比（240 帧同种子）：平均非空字符 68 → 176，`@` 占比从 4.9% 升到 6.4%，同时可见爆裂从 1 团增加到 2~3 团。

## AI 幻觉 / 缺陷汇总（答辩用）

| # | 现象 | 根因 | 如何发现 | 修正 |
| --- | --- | --- | --- | --- |
| 1 | Agent 声称「本机没有 gcc，无法编译验证」，交付未编译代码 | 只搜了 PATH/msys64/Program Files，没搜 RedPanda-CPP；把「我没找到」当成「不存在」 | 我给出编译器绝对路径后一编就过 | Prompt 里写死 gcc 绝对路径 + 要求「编译失败必须自己修到通过」 |
| 2 | `apply_patch verification failed: invalid patch` | GLM 不按 Codex 的 `*** Begin Patch` freeform 格式输出 | 观察 `codex exec` stderr | 非 OpenAI 模型下改用整文件重写 / shell 写入，不依赖 patch 工具 |
| 3 | 声称「已按实际耗时补齐帧率」，实测 60fps 只有 40fps | 只验证了算术，不知道 Windows `Sleep` 15.6ms 粒度 | 用 `--frames 300 --fps 60` 实测墙钟时间 | 换可等待定时器 + 末段自旋，实测 4.96s/5.00s |
| 4 | 画面边缘偶发「幽灵像素」 | `clear_canvas` 清 `cols×rows`，`draw_pixel` 却按 `MAX_COLS/MAX_ROWS` 判界，边缘残留上一帧亮度 | 读代码发现判界范围不一致 | 整幅清空 |
| 5 | 粒子偶尔整团消失 | 火箭在 `y<0` 爆炸，粒子出生即触发越界删除 | 长时间跑 + 统计每帧粒子数 | 爆炸点 y 夹紧到 1 |
| 6 | **程序启动即崩溃（0xC0000005）**：`get_console_size` 返回 `1696502567 × 32758`，`memcpy` 直接拷 1.7 GB | Agent 把 `get_console_size` 改成「读取失败时沿用传入的旧值」，但 `main` 里的 `int cols, rows;` **未初始化**，旧值是栈垃圾 | 跑 `--frames 1` 必崩；加 stderr 追踪打印出尺寸 | `int cols = 0, rows = 0;` 初始化 + `render_frame` 加尺寸防御 |

**结论**：Agent 擅长快速搭骨架（R1 一次成型、R2 增量结构合理），但在**平台细节、边界条件、性能假设、状态初始化**四处最容易产生「叙述正确、行为错误」的幻觉，必须用可观测的测试（墙钟时间、逐帧统计、边界用例、异常尺寸）去证伪。

## R4：尺寸自适应 + 射线化（Agent 生成，选手收尾）

**Prompt 要点**（全文 `logs/R4/prompt.txt`）：

> 只改 firework.c，不回退已有功能。① 每 30 帧重读控制台尺寸，变化时清屏重绘，坐标仍按新尺寸校验；② 每次爆炸沿 64 方向、同方向多层粒子、速度由内向外递增，形成连续射线，外层寿命略短；只能用 `@ O o * . ,`；③ 自己用指定 gcc 编译、跑 300 帧计时与 3000 帧长跑后再回复。

**产出**：722 行，实现了 `RAY_DIRS=64`、`RAY_LAYERS=5`、`RESIZE_CHECK_FRAMES=30`，编译零警告。

**本轮问题**：

1. **崩溃 bug（幻觉 6）**：见上表，`--frames 1` 必崩。Agent 在日志里已经打印「Exit code: 0」并说「All modifications look correct」，但它只验证了**编译**，没验证**运行**，随后 GLM 配额耗尽（`Quota exceeded`），连自测都没跑完。
2. **改丢了「随机爆炸规模」**：R4 把爆炸固定成 64×5=320 粒子，赛题必做的「每次爆炸粒子数量随机」被覆盖。我改成 `RAY_LAYERS_MIN/MAX = 3/6`（192~384 粒子随机），既保留射线结构又恢复随机性。
3. 注释仍写「80~200 个粒子」，已同步更新。

**选手收尾**：初始化 `cols/rows`、加尺寸防御、恢复随机规模、调 `GRAVITY 0.030→0.014`、`PSPEED_MAX 0.60→0.85`、寿命 90~130，让爆裂更接近圆形而不是被重力压成锥形。

## R5：三种爆裂 + 二次爆裂 + 闪烁（选手手工，配额耗尽后）

**背景**：R4 结束后智谱 GLM 配额耗尽（连一条「回复两字」都返回 `Quota exceeded`），R5 无法再交给 Agent，由我按赛题允许的「选手评审 + 修复」角色手工实现，并在日志里如实标注。

**改动**：

1. **三种爆裂类型**（`choose_explosion_type`，牡丹 50% / 柳条 30% / 环形 20%）：
   - 牡丹：64 方向 × 4~8 层，速度由内向外递增；
   - 柳条：32 方向 × 10~16 层，速度更慢、整体压暗一档、重力 1.1 倍，形成下垂光丝；
   - 环形：64 方向 × 2~3 层、只有外圈、速度带更窄并加抖动，形成空心环。
2. **火星二次爆裂**：牡丹中 12% 粒子标记为 `KIND_SPARK`，寿命耗尽时在原位炸出 6 颗小火星（不递归）。
3. **闪烁**：12%~25% 粒子标记 `KIND_TWINKLE`，按寿命与横坐标错相位间歇压暗。
4. **重力曲线**：`vy += GRAVITY * (0.55 + 1.15 * age)`，刚炸开时轻、临近熄灭时重。

**实测**：600 帧内共 71 次爆炸，类型分布 牡丹 37 / 柳条 23 / 环形 10，三种形态确实都出现了；`-Wall -Wextra` 零警告，300 帧 @60fps 4.94s，3000 帧长跑 3s 无崩溃。

**遗留**：柳条在静帧里辨识度仍一般（字符终端分辨率限制），动图里下垂感明显一些；若要更强，需要给柳条加连续尾迹粒子（预算约再 +50 行）。

在 R5 基础上补四个“像真的”的细节，全部是渲染/更新层的小改动：

| 效果 | 做法 | 代码位置 |
| --- | --- | --- |

**注意**：拖尾让画面密度接近翻倍，在 80×24 小窗口下会显得偏满；建议演示用 100×30 以上窗口，录制版统一用 120×36。
